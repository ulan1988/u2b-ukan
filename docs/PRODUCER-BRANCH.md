# Филиал-производитель — проект потока «лист → изделие → продажа головному»

Статус: **основа заложена** (2026-08-12). Backend производства уже есть; здесь — как всё связать.

## Идея (со слов владельца)
- Филиал-**производитель** берёт **листы** (сырьё) от головного офиса.
- Делает из них **изделия**.
- Продаёт изделия **только через головной** (единственный покупатель филиала = головной).
- Головной отправляет филиалу товары (сырьё) и продаёт готовое конечным клиентам.

## Организации и склады (уже есть в прод-базе)
- **Головной** `U2B головной` — `kind='hq'`, `e015c65a…`. Склад: **Центр-Склад** (+ тестовый).
- **Филиал-производитель** — `kind='producer_seller'`, `50d5113c…`. Склад: **«Склад производителя»** (заведён — сырьё + готовые изделия).
- Филиал-продавец — `kind='seller'`, `6673fad6…` (пока не в этом потоке).

## Мосты между книгами (contragents.orgRefId — заведены)
Каждая орг ведёт свою книгу; связь через контрагента с `org_ref_id`:
- В книге **головного** есть контрагент **«Филиал-производитель»** → орг `50d5113c` (головной шлёт ему листы и покупает у него изделия).
- В книге **филиала** есть контрагент **«U2B головной»** → орг `e015c65a` (филиал продаёт изделия только ему).

## Поток (4 шага)
```
[1] Головной ──transfer(листы)──▶ Склад производителя
[2] Филиал: production  листы(input −) ──▶ изделия(output +)
[3] Филиал ──sale(изделия)──▶ Головной   (зеркально: у HQ это purchase, приход на Центр-Склад)
[4] Головной ──sale──▶ конечный клиент
```

### Шаг 1 — Перемещение листов HQ → филиал (`type='transfer'`)
Списание с Центр-Склада головного (`−qty`) + приход на «Склад производителя» (`+qty`), одним документом-перемещением. Сейчас: **схема готова (`type='transfer'`), логики НЕТ** — построить сервис `createTransfer` (from/to склад, movements ±) + DTO + роут + UI. Меж-орг: два склада в разных орг → две проводки `stock_movements`, документ-перемещение как основание.

### Шаг 2 — Производство листы → изделия (`type='production'`)
**УЖЕ РАБОТАЕТ (backend):** `createProduction` (`document.service.ts`): `inputs`(листы, role=input, `−`склад) → `outputs`(изделия, role=output, `+`склад), размерное ценообразование `area=см×см/10000; amount=area×rate×qty`. DTO/роут/клиент есть. **Не хватает UI** (форма «Производство» в кабинете филиала) и переноса себестоимости Σ(input)→цена output + `doc_links` производство→сырьё.

### Шаг 3 — Продажа изделий филиал → головной (меж-орг, зеркальная)
В книге филиала — `sale` на контрагента «U2B головной» (`−` склад производителя). Зеркально в книге головного — `purchase` на контрагента «Филиал-производитель» (`+` Центр-Склад). Правило «продажа только через головной» = у филиала единственный контрагент-покупатель = головной. Сейчас: **меж-орг зеркальной проводки НЕТ** — построить на базе `orgRefId` (задел есть, в коде не используется). Опора: `postOrderInvoice`, `createSale/createPurchase`, `docLinks`.

### Шаг 4 — Продажа головного клиенту
Обычная продажа (`sale`) — **уже работает** весь конвейер (Приёмка→Исходящие→накладная→учёт).
