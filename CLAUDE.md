# u2b-ukan — ERP-ядро + CRM «Улкан» (торговля/производство металлом)

> Читать ПЕРВЫМ в каждой сессии. Планы: `PLAN.md` (ERP-ядро), `ULKAN-PLAN.md` (оперативка/канбан),
> `docs/PRODUCER-BRANCH.md` (поток лист→изделие), `docs/SCHEMA.md`. Память сессий: `~/.claude/.../memory/`.

## Стек и деплой
- **Next.js 14** (App Router, `--src-dir`) + TS + Tailwind + **Neon Postgres** (pooler) + **Drizzle ORM** + Zod.
- Код в папке **`nextjs/`** (не в корне). Деплой **Vercel** (Root Directory = `nextjs`), ветка **`master`**.
- Репозиторий публичный `github.com/ulan1988/u2b-ukan` — секреты только в `nextjs/.env.local` (в .gitignore).
- `.env.local`: `DATABASE_URL`, `AUTH_SECRET` (значение в **одинарных кавычках** — при парсинге в скриптах снимать кавычки и `\r`).

## Метод (СТРОГО по слоям)
`route (app/api/**) → dto (zod) → service (бизнес-логика) → repository (только Drizzle) → db`.
- Компоненты НЕ вызывают fetch напрямую — через `lib/api/*`. UI-токены: `lib/colors`, формат: `lib/adminFmt`.
- Номера документов: `lib/num`. Даты — локальный день (`today()`), не UTC-срез.
- Справочники (products/contragents/warehouses/users) — общие; Улкан НЕ дублирует, только FK.

## Организации (прод-база)
- **U2B головной** `hq` — `e015c65a…`, склад Центр-Склад.
- **Нипа листогиб** `producer_seller` (филиал-производитель) — `50d5113c…`, «Склад производителя».
- **Магазин Кристалл** `seller` (филиал-продавец) — `6673fad6…`.
- Мосты меж-орг: `contragents.orgRefId`. Плечо позиции: `leg` (1 = поставщик-филиал/производство, 2 = обычная), по совпадению имени пользователя-branch и контрагента (`lib/legDetect`).

## Карточка-заявка (Улкан)
- Экраны: `incoming → reception → outgoing → accounting → bookkeeping → archive`. Воркфлоу декларативно в `services/orderWorkflow.ts` (TRANSITIONS), диспетчер `POST /api/orders/[id]/action`.
- Закуп `kind='purchase'` (цель Центр-Склад), продажа `kind='sale'`. Позиции: `order_positions`.
- **Производство (кабинет мастера, филиал) — БЕЗ раскроя:** этап карточки в поле `prod_phase` `''`→`accepted`(Принял)→`working`(В работе)→`ready`(Готов к доставке)→`sent`(Отправлено) — отдельный стейт мастера, не конфликтует со статусом «В работе» головы. Приём: `produceAccept`; смена этапа: `produceStart`/`produceReady`. Отправка логисту **целиком или частями**: `POST /api/orders/[id]/send {posIds?}` → выбранные leg=1 позиции → leg=2, экран `outgoing`; когда leg=1 не осталось → «Отправлено». Позиции в кабинете — в шторке (чекбоксы). Раскрой/Распил/Листогиб/`setProdStage`/`cut_confirmed`/`consumeForCut` УБРАНЫ из потока (материал считается кабинетом листов). **Отправлено = карточка создана в Исходящих (расходная); ERP-накладная проводится на ДОСТАВКЕ логистом** (чтобы правки логиста — недовоз/брак — попали в документ).
- **Действия карточки (Ф-B, в шторке мастера):** 💳 Оплата (`orders.payment` = Долг/Наличка/Каспи, вся карточка); 📁 В проект (`orders.spec_project_id`, привязка к спец-проекту); ➕ Сплит (`POST /api/orders/[id]/split {posIds}` → выбранные позиции в НОВУЮ ЗК-карточку `prodPhase=accepted`, из исходной удаляются, ≥1 позиция должна остаться). `updateCard` умеет payment/specProjectId.
- **Логист правит перед доставкой:** в Исходящих логист меняет кол-во позиции (тап по кол-ву ✎) и убирает позицию (🗑) — `updatePosition`/`deletePosition`, пока карточка не доставлена (`editBlocked`). Правки попадают в накладную при проведении на доставке.
- **Касса мастера (Ф-C1) — прямая продажа без логиста:** в шторке нал/каспи/долг(авто)/сдача; «💵 Оплатить» (`services/cashier.service.payCard`, POST /api/orders/[id]/pay) проводит расходную (`postOrderInvoice` → у головного авто-приходная по мосту `orgRefId`), пишет нал/каспи в `payments` (счета филиала = как в ГО: «Основная касса»/«KASPI GOLD»/«Банковский счет»), долг=дебиторка, контрагент=заказчик иначе мост на головной (долг на головной). Карточка `prod_phase='sold'` → секция «💵 Продано». «↩ Отменить продажу» (`unpostSale`, DELETE) = сторно док + удаление оплат + карточка снова в работу (владелец правит после). Поля `orders.paid_cash/paid_kaspi/change_sum/change_from`.
- **Смена мастера (Ф-C2):** вкладка «💵 Смена» (`services/shift.service`, `/api/branch/shift`): доходы (продажи нал/каспи/долг за день по дате расходной накладной), производство в запас (docs production output за день), **расходы через «Деньги»** — ЗП (сотрудник+счёт+ручная сумма оклада, article='ЗП') и текущие (`fin_rows` с отрицат. суммой через `saveFinRow`), остаток по счетам, «Закрыть смену» (`postFinDay`). Ставку сотрудника НЕ храним — вводят руками.
- **Спец-проект мастера** (кабинет, вкладка «🎨 Спец проект»): собрать список моделькой → раскрой → «К логисту» (частями) минуя производство. Бэкенд `carveToLogist`.

## Проекты (call-off) и материал/спецификации — см. память `[[material-spec-model]]`, `[[projects-drawdown-model]]`
- **Проект** = мастер-список (`spec_projects` + `spec_project_items`), из него **выносим карточки по частям** (`carveCard`), остаток = qty − Σ(вынесено по `order_positions.spec_item_id`). Раздел админки «📁 Проекты».
- **Спецификация:** `spec_types` (тип изделия → стандартный см: Н=18, J=8, углы 11/25), `products.specTypeId`. Комплектующие = **13 базовых товаров «Без цвета»**; конкретное изделие собирается в модельке (**база + цвет + см → имя «Изделие 7004 26 см»**, `productId`=база для отчётов). Пикеры: `NomInline` (инлайн), `NomPicker` (каталог), быстрый набор `lib/nomTree` (accessoryKinds, «Изделие» с `measure`).
- **Склад материала** = физические КУСКИ (`material_pieces`), НЕ м²: лист 125×200 (`kind='sheet'`), обрезь = полоса по ширине (`kind='remnant'`), **обрезь <4 см (`MIN_REMNANT_CM`) → в расход**. Раздел «🧱 Материал» (типы / склад-ревизия / привязка). Приход листов — из приходной накладной; на складе только ревизия. Раскрой: `lib/production` (`optimizeCut`, режем по ширине 125). Матчинг листа: по цвету, только НЕ матовый, толщина неважна. ⏳ Ф2 (раскрой↔склад) — не построено.

## Рабочие правила (важно!)
- **«Закоммить» = commit + push вместе** (ветка master), без переспрашивания. Доводить задачу до конца/задеплоя.
- Каждый значимый шаг: **`tsc --noEmit` → `next build` → смоук → commit → push**. Обновлять план-файлы и память.
- Отвечать **кратко**, без длинных перечней опций. Уточнять только когда реально меняет план.
- Смоук: минтить JWT (`jose`, cookie `u2b_session`, секрет из `.env.local`) + бить по `localhost:3000`; чистить тест-данные после; убивать лишние `next dev` (порты 3000+).
- Схема БД: правка `src/db/schema.ts` → `npx drizzle-kit push --force`.
- **Bash-инструмент = Git Bash (POSIX)**, НЕ PowerShell: НЕ использовать here-string `@'...'@` (лезет `@` в коммит) — сообщения коммита через файл `-F`. Временные скрипты — в scratchpad или удалять после.
